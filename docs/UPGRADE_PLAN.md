# App Review Insights · 三套升级方案（详细设计）

> 基于 LaienTech 评估书（D:\README.md）的 Evaluation Criteria / Important Notes /
> Technical Requirements and Notes 三项核验通过之后的可选增强。
> 约束：前端保持**零第三方依赖**（原生 Canvas2D / SVG / DOM），后端保持纯标准库。

---

## 方案 A：数据可视化套件（Bento 图表）

**定位**：把「数字与表格」升级为「一眼看懂的分析仪表盘」，直接命中评分标准
「评论处理逻辑合理」「模型语义分析价值可视」「结论严谨度可感知」。

### A1 评分分布环形图（替代横向条）
- 交互：环形图 5 段（5★→1★ 顺时针），中心显示平均分与评论总数；hover/点击某段
  高亮并在图下显示该星级条数 + 占比（沿用现有 `pctShares` 口径，保证合计 100%）。
- 实现：单 `<canvas>` 自绘（`arc` + 渐变描边），随 Tab 激活重绘；颜色沿用设计令牌
  （`f5` 绿 → `f1` 红）；`prefers-reduced-motion` 下不播旋转入场。
- 数据：直接使用 `clean_stats.rating_distribution`，无需新接口。
- 工作量：0.5–1 天。

### A2 主题聚类气泡图 + 关键词权重
- 交互：每个主题一个气泡（面积 ∝ 样本数，颜色 = 主题色）；hover 显示
  「主题名 / 样本数 / 占比」；点击气泡滚动到对应主题卡片并高亮 1.5s。
- 实现：Canvas 圆形打包布局（纯算法，无 d3）；气泡入场 stagger 缩放；
  关键词按出现频率做字号大小（复用 `kw-chip` 视觉）。
- 数据：`topics.json`（count + keywords）。
- 工作量：1–1.5 天。

### A3 发现置信度条形图 + 阈值色带
- 交互：所有发现按 `confidence` 排序的横向条，背景分三段色带
  （<0.5 灰黄=证据不足、0.5–0.8 蓝=中等、>0.8 绿=高）；每条带 provenance 徽章
  （统计/模型）与样本数；hover 显示 uncertainty 与冲突数。
- 实现：纯 CSS 条形 + `title`/自绘 tooltip；复用 `.conf-track/.conf-fill`。
- 数据：`findings.json`；无需新接口。
- 工作量：0.5 天。

### A4 全链路溯源图（评论 → 发现 → 需求 → 用例）
- 交互：横向四层泳道（评论 / 发现 / 需求 / 用例），节点可点击：
  评论节点 → 打开「原始评论」Tab 并高亮该行；发现/需求/用例节点 → 跳到对应 Tab
  高亮卡片。断链（移除/假设）用红/黄描边。
- 实现：内联 SVG（`<line>` + `<rect>` + `<text>`），按 `traceability.json` 的
  checks/removed/assumption 计算布局；连线颜色 = 校验通过（绿）/缺失（红）。
- 数据：`traceability.json` + `findings/requirements/testcases`。
- 工作量：1.5–2 天（本方案最重的一块）。

### A5 版本规划甘特条
- 交互：需求按 `planned_version`（V1/V2…）分泳道，横向条长度 ∝ 需求数量，
  条上直接写 `R1·标题·P0`；hover 显示需求详情摘要。
- 实现：纯 CSS Grid + 渐变条，零 Canvas。
- 数据：`requirements.json`。
- 工作量：0.5 天。

### A6 评论时间趋势（200 条窗口）
- 交互：把最新 200 条按天聚合的折线/面积图，标注「仅展示最新 200 条采集窗口」
  与首次/末次评论日期；用于展示 200 条上限策略的合理性。
- 实现：Canvas 折线 + 渐变填充；X 轴时间刻度自适应。
- 数据：`raw` 接口返回的 `updated` 字段聚合。
- 工作量：0.5–1 天。

### 共通实现约束（A1–A6）
- 全部自绘，不引 d3/chart.js；每张图独立初始化/销毁，切 Tab 不泄漏。
- 颜色一律取自 `:root` 设计令牌；动画 150–450ms；`prefers-reduced-motion` 全部降级为静态。
- hover 目标 ≥ 44px 热区；数值一律文字可见（不只靠颜色）。

**合计工作量：4–6 天；对考核加分：Eval #2/#3/#4/#6。**

## 方案 B：演示型产品工作台

**定位**：让面试官 3 分钟内无引导上手，把「进度 → 交付物 → 证据」串成一条可点击的线。

### B1 流水线侧栏导航（S0–S8）
- 左侧固定窄栏：8 个阶段点（S0 范围 … S8 汇总），当前运行态实时打点
  （沿用进度事件状态色）；点击任意阶段跳转到对应产物 Tab。
- 实现：纯 DOM + 锚点滚动；运行中只读，完成后可点。
- 工作量：0.5 天。

### B2 PRD 评审模式
- 每条需求卡进入评审态后出现三按钮：**接受**（保持 kept）/ **标记假设**（assumption）/
  **删除**；下方可写一条批注；操作结果汇总到「评审结论」区，导出时反映。
- 实现：前端本地状态对象（不落盘，保证数据不被污染）；导出时附加评审章节。
- 工作量：1 天。

### B3 证据双向跳转（最推荐先做）
- 发现/需求里的评论 chip → 点击弹出 `<dialog>` 显示该评论原文（星级/版本/日期/正文），
  数据来自现有 `stage=raw` 接口；评论列表里的来源/ID 也可反查它支撑了哪些发现。
- 实现：`/api/artifacts?stage=raw` 已就绪，前端加 Map<review_id, review> 缓存。
- 工作量：0.5–1 天。

### B4 全局筛选器（星级 / 版本 / 语言）
- 摘要页顶部一组筛选 chip（全星级 / 最低星级 / 语言 / 版本），切换后所有 Tab
  联动过滤（前端过滤渲染数据，不动后端产物）。
- 实现：把各 Tab 渲染函数改为「先过滤再渲染」；空结果显示「筛选后无数据」。
- 工作量：1 天。

### B5 一键导出报告（Markdown / JSON）
- 按钮生成分析报告：摘要+范围+清洗统计+主题+发现+PRD+用例+追溯+数据说明，
  用 Blob 下载 `.md` / `.json`；评审批注一并写入 Markdown。
- 实现：前端把 `window.__summary` + 各 stage 数据序列化组装。
- 工作量：0.5 天。

### B6 面试演示模式
- 右上角开关：开=隐藏 LIVE 滚动条与后台细节、聚焦「输入→进度→结论」主链路；
  默认加载示例 App（839285684）离线缓存，无网络也能完整演示。
- 工作量：0.5 天。

**合计工作量：4–5 天；对考核加分：Eval #5/#6、Important Notes「压力测试可演示」。**

## 方案 C：AI 协作者模式（最能展示模型驱动与防幻觉）

**定位**：把「防幻觉」「证据绑定」从后台逻辑变成面试官可当场验证的交互。

### C1 追问面板
- 任意发现/需求卡片底部「追问」按钮 → 内联对话框提问
  （如“这条需求的证据够吗？”），提交 `POST /api/ask`。
- 后端：新端点复用 `LLMClient` + 新提示词；请求体带**该结论的 review_id 白名单**，
  系统提示词强制只引用白名单；输出经 JSON 校验 + 引用过滤，失败降级为
  「模型不可用」明确文案（延续现有降级策略）。
- 工作量：1–1.5 天（前后端）。

### C2 挑战模式（反例验证）
- 输入一条反例评论（或选一条已有评论）→ 询问“这条评论是否推翻/削弱该发现？”；
  模型输出 支持/削弱/推翻 + 建议的 confidence 调整与新增 conflicts。
- 实现：复用 `/api/ask` 请求结构，结果只作建议展示，不自动改产物（保持数据诚实）。
- 工作量：1 天。

### C3 证据链浏览器（树形）
- 把 A4 的溯源图改成可展开树：根=用例 → 需求 → 发现 → 评论，每层显示
  通过/缺失/假设状态；点击节点在下方「原文/字段」面板展示详情。
- 实现：复用 A4 的数据遍历，渲染为 `<details>` 树或 SVG；建议 A4 与 C3 二选一或合并。
- 工作量：1–1.5 天（若复用 A4：0.5 天）。

### C4 低置信度自动折叠
- `confidence < 0.5` 的发现默认折叠为一行「⚠ 证据不足，点击展开」，
  展开后展示 uncertainty/conflicts；规则在渲染层实现。
- 工作量：0.3 天。

### C5 防幻觉检查日志可视化
- 「追溯校验」Tab 增加一块「引用白名单拦截记录」：本次运行丢弃了哪些模型引用
  （ID 不在白名单）、哪些结论被 S7 删除/标假设——把 docs/AI.md 的防幻觉设计
  变成可见的审计日志。
- 实现：pipeline 在 progress/artifacts 里补 `dropped_refs` 字段（后端小改）+ 前端列表。
- 工作量：0.5–1 天（含后端字段）。

**合计工作量：4–6 天；对考核加分：Eval #3/#4、Important Notes「模型驱动+防幻觉」。**

## 推荐实施路线

| 阶段 | 内容 | 预期天数 | 验收标准 |
|---|---|---|---|
| P0（先见效） | A1 环形图 + A3 置信度条 + B3 证据跳转 + C4 折叠 | 2–3 天 | 三个 Tab 数据可视化上线；点证据 chip 能看原文；低置信发现折叠 |
| P1（主体） | A2 气泡 + A5 甘特 + B1 侧栏 + B2 评审 + A6 趋势 | 2–3 天 | 摘要/主题/需求页全部图表化；侧栏可跳转；评审可批注 |
| P2（亮点） | A4/C3 溯源图 + C1 追问 + C2 挑战 + C5 拦截日志 + B4/B5/B6 | 3–4 天 | 全链路图可点；追问/挑战可对话；拦截记录可见；一键导出 + 演示模式 |

> 建议顺序：P0 性价比最高（每项都直接提升观感与严谨度展示）；
> 若面试时间紧，P0 + B3 + C5 已足够形成「可视化 + 证据可点 + 防幻觉可见」的完整故事。

## 风险与对策
- 图表复杂度失控：所有图坚持“一个 canvas/svg 一个职责”，超 1.5 天的项先做静态版再补交互。
- 与 LLM 相关的新端点（C1/C2）：沿用现有提示词白名单/降级框架，绝不返回无引用结论；
  先做 C4/C5（无网络依赖），再上 C1/C2。
- 数据一致性：筛选（B4）只作用于渲染层，产物文件永不被前端改写（评审批注 B2 同理）。
